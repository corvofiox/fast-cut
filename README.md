# Fast Cut

极简 Windows 视频裁剪工具。核心承诺是**剪辑位置精确到帧**：入点绝不吸附关键帧，你剪掉的
素材一秒都不会回到产物里。做法是"该拷的照拷、拷不动的只重编入点那一小段"——入点正好落在
关键帧上时整段流拷贝（不转码、不改画质），落在 GOP 中间时只把入点那一小段做有损重编码
（CRF 18、同 profile），其余仍是流拷贝。可变帧率源、以及没有同编码重编码器的源（如 MPEG-4 ASP）
会整段重编码，界面与导出自检都会明确说出来，不偷偷做事。

一条明确的边界：**带字幕的源，字幕按文本重新计时**。ffmpeg 逐段定位 Matroska/MP4 的字幕轨
不可靠（实测会整条漏掉落在切割窗口里的字幕，也会把已删区间的字幕串回来，而且"漏一条+串一条"
会让条数刚好相等），所以段里不带字幕，改成把 SRT/ASS 抽成文本、按保留区间映射到成片时刻、
在拼接那一步一次性上轨。位图字幕（PGS/DVD 等）无法按文本重排，这种源的分段导出仍会被自检拒绝
并说明原因，绝不静默交出字幕错位的文件。

交互按**键位优先**设计：没有入点 / 出点 / 分割 / 删除 / 缩放这些按钮，剪辑动作全走键盘
（`W` 分割、`Q` / `E` 涟漪删除、`J K L` 变速、`,` `.` 逐帧、`Shift+←/→` 跳关键帧、
`Ctrl+Z` / `Ctrl+Y` 撤销重做）。时间轴上顶部一条是刻度尺兼播放头手柄，下面整条胶片可以
拖动改片段顺序、单击选中，两者都不会移动播放头。

## 环境

- Windows 10/11，Node.js 20+
- `npm install`

### 构建 exe 前需要自备 ffmpeg

`vendor/ffmpeg/` 里要放 `ffmpeg.exe` 与 `ffprobe.exe`（该目录被 `.gitignore` 排除，不入库）。
electron-builder 会把它复制进 `resources/ffmpeg`，打包版**只用内置的这一份**，不提供用户覆盖入口。
注意：常见的公开构建是 GPL 编译的，自行分发 exe 时需一并履行相应义务。

## 命令

```bash
npm start              # 开发运行
npm run core:test      # 剪辑内核单元测试
npm run smoke          # 端到端自检：开真窗口跑完整剪辑 + 导出 + 时间轴交互
npm run core:codecs    # 编解码矩阵：11 种容器/编码 × 2 种导出模式 × 换封装，帧数与时长都要贴计划
npm run dist           # 打包 → dist/Fast-Cut-Setup-<版本>-x64.exe（NSIS 安装向导）
npm run dist:dir       # 只出 dist/win-unpacked/，调打包配置时快得多
```

## 隐私

无遥测、无网络请求。导出只写用户指定的目标文件：目标已存在或目标就是源文件时直接拒绝，
绝不覆盖用户的素材。
